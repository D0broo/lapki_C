# Лабораторна робота 5 — динамічні двовимірні матриці дійсних чисел (Варіант 10)

**Тема:** динамічні матриці `double **`, робота з дійсними числами, пошук екстремумів відносно головної діагоналі, транспонування, множення матриць, сортування рядка та суми.

**Варіант 10 (парний).** Матриця `A` — квадратна `na × na` (за замовчуванням `na = 10`). Максимум шукається по **всій** матриці `A`, а мінімум — **строго під головною діагоналлю**, тобто лише для `i > j` (`i = 1..na-1`, `j = 0..i-1`). Матриця `B` має розмір `nb × mb`; для множення `A × B` потрібно `nb = na`.

Джерело: [`main.c`](main.c). Збірка — [`Makefile`](Makefile).

## 1. Постановка задачі

1. Користувач вводить `na`, `nb`, `mb` (усі в межах `2..20` / `1..20`; порожній рядок — значення за замовчуванням `10`, `10`, `5`).
2. Кожна матриця ініціалізується одним із режимів:
   - `1` — введення з клавіатури (рядок матриці = один рядок вводу);
   - `2` — за формулою: `A[i][j] = i + j`, `B[i][j] = i + j + 0.5`;
   - `3` — випадкові дійсні числа в `[-50; 50]`.
3. Матриці друкуються з точністю `%.3f`, після чого програма чекає натискання Enter.
4. Меню дозволяє багаторазово виконувати всі операції, переініціалізувати матриці та вийти з повним звільненням пам'яті.

## 2. Функції

```c
void    clear_memory(double **matrix, int rows);
double **memory_allocation(int rows, int cols);

static void    max_and_min_below(double **A, int na);
static double **transpose_b(double **B, int nb, int mb);
static double **mult_a_b(double **A, int na, double **B, int nb, int mb);

/* Обов'язкова сигнатура за умовою: */
void sort_row(double *row, int size);

```

Усі матриці виділяються явно як `double **` (масив покажчиків на рядки, кожен рядок — окремий `malloc`). VLA не використовуються. Кожен `malloc` перевіряється; у разі невдачі вже виділене звільняється, друкується помилка, програма завершується коректно. Глобальних змінних немає.

## 3. Завдання 4.1 — максимум усієї `A` та мінімум під діагоналлю

- Максимум: початкове значення `A[0][0]`, повний подвійний цикл `i = 0..na-1`, `j = 0..na-1`.
- Мінімум: початкове значення `A[1][0]` (перший елемент під діагоналлю), цикл `i = 1..na-1`, `j = 0..i-1`. Елементи на діагоналі та над нею **не розглядаються** — це і є правило парного Варіанта 10.

Функція друкує значення та індекси обох екстремумів. Якщо `na < 2`, мінімум під діагоналлю не визначений — програма повідомляє про це й не звертається до неіснуючих елементів.

## 4. Завдання 4.2 — транспонування `B`

`transpose_b` виділяє нову матрицю `mb × nb`, копіює `T[j][i] = B[i][j]` і повертає її. У `main` стара `B` звільняється, вказівник замінюється, `nb` і `mb` міняються місцями — транспонування відбувається **в пам'яті**, а не лише під час друку.

Після транспонування `B` стає `mb × nb`, тому наступне множення `A × B` може стати несумісним (`na != nb`). Програма коректно друкує

```text
Error: A x B is impossible: na = 10 but nb = 5.
```

і повертає `NULL`, не виділяючи пам'ять під `C`.

## 5. Завдання 4.3 — множення `C = A × B`

Перевіряється `na == nb`. Якщо умова виконується, виділяється `C` розміру `na × mb` і обчислюється

$$C_{ij} = \sum_{k=0}^{na-1} A_{ik}B_{kj}, \qquad i = 0..na-1,\ j = 0..mb-1.$$

`C` повертається в `main`, друкується та звільняється через `clear_memory`.

## 6. Завдання 4.4 — сортування рядка `A`

Обов'язкова функція:

```c
void sort_row(double *row, int size)
{
    int i;
    for (i = 1; i < size; ++i) {
        double key = row[i];
        int j = i - 1;
        while (j >= 0 && row[j] > key) {
            row[j + 1] = row[j];
            --j;
        }
        row[j + 1] = key;
    }
}
```

Це сортування вставками за зростанням. У `main` виклик має вигляд `sort_row(A[row], na)` — передається саме покажчик на вибраний рядок (1D масив із `na` елементів), як вимагає сигнатура. Індекси рядків перевіряються на `0..na-1`.

## 7. Завдання 4.5 — суми рядків `A` і стовпців `B`

- Для кожного рядка `A`: $\sum_{j=0}^{na-1} A_{ij}$.
- Для кожного стовпця `B`: $\sum_{i=0}^{nb-1} B_{ij}$.

Суми накопичуються в `double` і друкуються з індексами.

## 8. Ручна перевірка на формульних матрицях (`na = nb = 10`, `mb = 5`)

`A[i][j] = i + j`:

- максимум усієї матриці — `A[9][9] = 18`;
- мінімум **строго під** діагоналлю — `A[1][0] = 1` (у `A[0][0] = 0` не враховується, бо це діагональ).

`B[i][j] = i + j + 0.5`:

- сума стовпця `j`: $\sum_{i=0}^{9}(i + j + 0.5) = 45 + 10j + 5 = 50 + 10j$, тобто `50, 60, 70, 80, 90`;
- сума рядка `i` матриці `A`: $\sum_{j=0}^{9}(i+j) = 10i + 45$, тобто `45, 55, …, 135`.

Перевірка елемента `C[0][0]`:

$$C_{0,0} = \sum_{k=0}^{9} A_{0,k}B_{k,0} = \sum_{k=0}^{9} k(k + 0.5) = \sum k^2 + 0.5\sum k = 285 + 22.5 = 307.5,$$

що збігається з надрукованим `307.500`.

## 10. Меню, пауза та завершення

```text
Menu:
  1 - max of the whole A and min strictly below the diagonal
  2 - transpose B in memory (mb x nb)
  3 - multiply C = A x B
  4 - sort a selected row of A
  5 - row sums of A and column sums of B
  6 - print matrices A and B
  7 - re-initialize matrices
  0 - exit
```

Після кожного пункту (1–7) програма друкує `Press Enter to continue...` і чекає рядок вводу — це дає змогу прочитати результат перед поверненням у меню. Пункт `0` завершує роботу: усі динамічні матриці звільняються, друкується `Memory released. Goodbye.`

Введення чисел перевіряється: порожній рядок для розмірів означає значення за замовчуванням, а некоректне число або вихід за діапазон — повторний запит. Для матриць з клавіатури кожен рядок мусить містити рівно `na` (або `mb`) дійсних чисел.
